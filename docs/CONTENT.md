# 内容维护指南

新增内容的流程是：**创建文章文件夹 → 编写 `index.md` → 添加素材 → 本地预览 → 提交发布**。网站会自动读取这些文件，生成文章列表、正文和目录。

本文中的路径都从项目根目录算起，也就是能看到 `package.json` 的文件夹。下面的文章和素材名称用于演示写法，需要自行创建。

## 先找到要修改的文件

| 想修改什么 | 修改位置 |
| --- | --- |
| 新增或修改一篇文章 | `content/entries/文章文件夹/index.md` |
| 文章中的图片、视频、封面、字幕 | 放在这篇文章的文件夹内 |
| 首页问候、职业、兴趣、个人介绍 | `content/site.yml` |
| 栏目名称、栏目说明、经历条目 | `content/site.yml` |
| PDF 简历 | 文件放在 `content/files/`，链接填在 `content/site.yml` |

日常写作主要使用 `content/`。`site/` 保存网页代码，`dist/` 是程序生成的发布文件，更新文章时无需修改它们。网站功能和操作说明见 [PRODUCT.md](PRODUCT.md)。

## 新增一篇文章

### 1. 创建文章文件夹

在 `content/entries/` 下新建文件夹，例如 `my-note`。建议使用小写英文、数字和短横线。

```text
content/entries/
├── .gitkeep
└── my-note/
    └── index.md
```

每篇文章有自己的文件夹，里面必须有 `index.md`。`.gitkeep` 只是用来保留空目录，可以继续留着。

### 2. 填写标题、栏目和正文

将下面的模板复制到 `index.md`，再换成自己的内容和实际日期：

```markdown
---
title: "我的第一篇项目记录"
sections: [project]
publishedAt: "2026-11-07"
---

这里写文章的开头。

## 项目介绍

这里介绍项目的目的和过程。

## 展示结果

这里记录结果和下一步想法。
```

顶部两行 `---` 之间是文章信息，后面是正文。常用字段如下：

| 字段 | 是否必填 | 用途 |
| --- | --- | --- |
| `title` | 是 | 文章标题，显示在正文和列表中 |
| `sections` | 是 | 文章所属栏目 |
| `publishedAt` | 否 | 创建日期，格式为 `"YYYY-MM-DD"` |
| `updatedAt` | 否 | 手动指定更新日期；省略后，在生成网站时按本篇 Git 提交记录计算 |

栏目对应关系为：

| 栏目 | 填写方式 |
| --- | --- |
| 生活 | `sections: [life]` |
| 经历 | `sections: [resume]` |
| 项目 | `sections: [project]` |

同一篇文章可以属于多个栏目，例如 `sections: [resume, project]`，不需要复制文章。

文章标题由 `title` 提供。正文中的小节标题使用 `##`，下一层使用 `###`；至少两个有效小节标题时，网站会自动显示“本页目录”。正文里不要再写 `#` 大标题，这会导致检查失败。

## 添加图片和视频

把素材放进对应的文章文件夹，再在正文中引用。可以直接放在文章目录，也可以用 `photos/`、`videos/` 和更深的子文件夹分类。例如：

```text
my-note/
├── index.md
├── photos/
│   └── result.jpg
└── videos/
    ├── demo-a.mp4
    ├── demo-a.poster.png    # demo-a 的可选封面
    ├── demo-a.zh.vtt        # demo-a 的可选中文字幕
    ├── demo-b.mp4
    └── earlier/
        └── demo-a.mp4      # 不同子目录可以使用相同视频文件名
```

### 图片

在希望出现图片的位置，单独写一段：

```markdown
![项目截图的简要说明](./photos/result.jpg)
```

`./` 表示当前文章文件夹。方括号里写图片说明，圆括号里写文件位置；多层文件夹按层级继续填写，如 `./photos/results/final.png`。支持 SVG、PNG、JPG、JPEG、WebP、GIF、AVIF 和 BMP 图片。

访客点击图片后，会在同一页面查看大图；按 `Esc`、右上角的 × 或图片外空白处关闭。

也支持从编辑器粘贴的 HTML 图片，以及常见的 HTML 链接、段落、标题、列表、表格和文字强调。例如：

```html
<p>项目主页：<a href="https://github.com/LizPink/2026Fall-Renderer-from-Scratch">打开项目</a></p>
<img src=".\photos\result.jpg" alt="项目截图" style="zoom:33%;">
```

HTML 图片与 Markdown 图片使用相同的素材复制、版本化和同页大图预览。`alt` 用作图片说明；HTML `figure` 中的 `figcaption` 可提供单独说明。说明在图片下方居中，不额外显示大图提示文字。图片的 `width="320"`、`style="width:50%"` 和 `style="zoom:33%"` 可调整显示大小，仍受正文可用宽度、自然宽度和网站媒体上限约束。

HTML 的 `h2`、`h3` 也会加入本页目录。正文不用 `h1`；文章标题仍填写在元信息的 `title` 中。代码块和行内代码里的 HTML 继续原样展示。解析器只保留常见排版标签，不执行脚本或事件属性；不支持的标签以文字显示。

### 视频

MP4 使用相同的引用方式：

```markdown
![第一段项目演示](./videos/demo-a.mp4)

![第二段项目演示](./videos/demo-b.mp4)

![早期版本演示](./videos/earlier/demo-a.mp4)
```

一篇文章可以引用多个 MP4，每段都会显示独立的播放控件。需要封面和字幕时，将它们放在视频所在的同一个文件夹，按视频名称配套命名：

| 文件 | 用途 |
| --- | --- |
| `videos/demo-a.mp4` | 视频本身 |
| `videos/demo-a.poster.png` | 播放前显示的封面，也支持 `.svg`、`.jpg`、`.webp` |
| `videos/demo-a.zh.vtt` | 中文字幕 |

封面和字幕都可以省略；提供时会自动关联，只需在正文中引用 MP4。例如 `demo-b.mp4` 只匹配同一文件夹中的 `demo-b.poster.*` 和 `demo-b.zh.vtt`。不同子目录里的同名视频各自匹配身边的文件，不会混用。

Markdown 和 HTML 资源路径均兼容 `/`、`\`，例如 `./images/photo.jpg` 与 `.\images\photo.jpg`。素材仍应保存在本篇文章文件夹内。解析时会把指向本篇素材的本机绝对路径或 `file:` 链接转换为可发布的相对路径，不改写原始 `index.md`。

跨电脑或在线构建时，旧绝对路径中的 `content/entries/当前文章名/` 可用于定位当前文章素材；其他文章、文章目录之外的文件和网络共享路径不读取。普通网页超链接可使用 HTTP、HTTPS 或邮件链接，图片及视频等素材需要随文章存放，不能引用远程媒体。推荐优先使用相对路径，便于移动整篇文章。

**仅复制文件不会让它出现在页面上，还需要在正文引用。**

## 更新、删除和日期排序

### 修改已有文章

直接编辑这篇文章的 `index.md`。修改标题、正文或日期，都不用改文件夹名。

保留原来的 `publishedAt`。通常可以省略 `updatedAt`：首次创建时，更新日期与创建日期相同；以后提交这篇文章的正文或素材改动，生成网站时会根据 Git 中的后续提交记录计算更新日期。提交时间按北京时间（`Asia/Shanghai`）换算为日期。

需要自己指定更新日期时，再填写 `updatedAt`，格式同样为带引号的 `"YYYY-MM-DD"`。**手填的更新日期优先于自动计算结果**，以后希望恢复自动计算时删除该字段即可。

| 日期填写情况 | 正文显示 |
| --- | --- |
| 首次创建，未填写 `updatedAt` | “创建于”和“更新于”都显示创建日期 |
| 之后提交了这篇正文或素材的修改，未填写 `updatedAt` | “更新于”显示最近一次后续内容提交的北京时间日期 |
| 手动填写 `updatedAt` | “更新于”始终使用所填日期 |
| Git 历史不完整、没有记录或 Git 不可用 | 未手填更新日期时，回退显示创建日期 |
| 没有手填日期，也没有后续内容提交记录 | 两项都显示 `—` |

未填写创建日期时，“创建于”显示 `—`。列表优先按更新日期从新到旧排列，没有更新日期时使用创建日期，没有任何日期的文章排在最后。栏目首页显示最近 10 篇，左侧目录列出全部文章。

生成网站时，会检查本篇文章文件夹内的正文、图片、视频及其他素材，包括子文件夹。已有文章的本地改动尚未提交时，仍显示最近已提交的更新日期；新文章尚未提交时，显示创建日期。仅重新构建网站、修改网页代码或修改其他文章，也不会刷新这篇文章的日期。程序不使用文件保存时间，也不会把计算结果写回 `index.md`。

### 修改链接或删除文章

文件夹名会成为链接的一部分：`my-note` 属于项目栏目时，可以通过 `#project/my-note` 打开。改文件夹名会改变链接，因此发布后尽量保持名称稳定。

删除文章时，删除它的整个文件夹即可。保存并重新发布后，网站会移除这篇文章和对应的已发布素材；原来的文章链接也会失效。

## 修改首页、栏目和简历

这些内容统一保存在 `content/site.yml`，通常只需修改对应的文字：

| 配置项 | 页面中的位置 |
| --- | --- |
| `name` | 网站名称 |
| `greeting` | 首页问候语 |
| `role` | 首页“职业”，只填值，例如 `学生` |
| `interests` | 首页“关注”内容，每行一个条目 |
| `about.paragraphs` | 首页个人介绍，每行一段 |
| `paths` 中的 `title`、`description` | 对应栏目的名称和说明 |
| `resume.sections` | 经历栏目展开后的经历条目 |
| `resume.pdfUrl` | 经历栏目中的 PDF 简历入口 |

保留栏目 `id` 为 `life`、`resume`、`project`，文章通过这些名称归入栏目。新增文章后，列表会自动生成，无需再往 `site.yml` 添加文章名称。

### 添加经历条目

在现有的 `resume` 配置中，按下面的结构填写 `sections`。已有 PDF 时保留原来的 `pdfUrl`，不要另外追加一份同名的 `resume` 配置：

```yaml
resume:
  sections:
    - heading: "教育经历"
      items:
        - title: "学校与专业"
          detail: "在这里填写学习时间和经历。"
  pdfUrl: ""
```

`heading` 是分组名称，`items` 是该组条目；每条都有 `title` 标题和 `detail` 说明。可以继续添加分组或条目。这些内容在经历栏目展开后显示。

### 添加 PDF 简历

1. 按需创建 `content/files/`，将简历放为 `content/files/resume.pdf`。
2. 在 `site.yml` 的现有 `resume` 配置中，将 `pdfUrl` 改为 `"./files/resume.pdf"`，保留已经填写的 `sections`。

没有 PDF 时，保持 `pdfUrl: ""`，页面会显示“PDF 待添加”。以后替换同名 PDF，只替换文件即可。

## 本地预览和发布

### 1. 启动预览

使用 Node.js 22 或更新版本，在项目根目录打开终端。首次使用时安装依赖：

```powershell
npm ci
```

以后编辑内容时，运行：

```powershell
npm run dev
```

保持终端开启，在浏览器访问 [http://127.0.0.1:4182/](http://127.0.0.1:4182/)。保存文件后，预览会自动更新；如果内容有错误，终端会提示具体文件和原因，浏览器保留上次成功的版本。

### 2. 检查内容

确认标题、栏目、日期和正文正确，图片与视频可以显示，窄屏阅读正常。结束预览时按 `Ctrl+C`，然后运行：

```powershell
npm test
```

这个命令会生成网站并执行检查。只想生成发布文件时，可单独运行 `npm run build`；日常检查后不必再重复运行。

### 3. 发布到线上

1. 将本次修改的文章、素材或配置提交到 Git。
2. 如果在开发分支，先将改动合并到 `main`，再推送 `main`。
3. 到 GitHub 的 Actions 页面查看发布结果。自动检查通过并部署成功后，[线上网站](https://lizpink.github.io/)才会更新。

推送开发分支只保存代码，不会更新线上网站。替换同名图片、视频或 PDF 时，程序会自动更新资源链接；发布成功后仍看到旧页面，可以按 `Ctrl+F5` 刷新。

本地提交后，运行 `npm run build` 并刷新浏览器，或重新启动 `npm run dev`，即可看到重新计算的更新日期。Git 提交本身不会刷新已开启的预览，日期也不会随每次保存跳动。

## 遇到问题时

| 现象 | 优先检查 |
| --- | --- |
| 新内容没有出现在预览中 | 文件夹里是否有 `index.md`；终端是否报告错误 |
| 文章出现在错误栏目 | `sections` 是否填了正确的栏目名称 |
| 图片或视频不显示 | 文件是否存在，名称和引用是否一致，是否用了 `/` |
| 日期导致检查失败 | 是否使用带引号的 `YYYY-MM-DD`，日期是否有效 |
| 修改后更新日期没有变化 | 是否已提交并重新生成网站；是否手填了 `updatedAt`；首次创建仍显示创建日期 |
| 没有出现本页目录 | 正文是否至少有两个 `##` 或 `###` 小节标题 |
| 粘贴的 HTML 没有效果 | 使用常见排版标签；代码块里的 HTML 和不支持的标签会作为文字显示 |
| 本地更新了，线上仍未更新 | 是否推送了 `main`，对应 Actions 发布是否成功 |
