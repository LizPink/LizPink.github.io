# 内容维护

本文介绍本站当前正式的 Markdown 内容维护流程。作者内容位于 `content/`，UI源码位于 `site/`，发布目录 `dist/` 由构建生成；线上版本以对应 GitHub Actions 部署结果为准。

## 平时修改哪些文件

```text
content/
├── site.yml                 # 品牌、问候、简介、简历和栏目文字
├── entries/
│   └── geometry/             # 一篇内容的稳定编号
│       ├── index.md          # 元信息与正文
│       └── demo-geometry.svg # 这篇内容引用的媒体
└── files/                   # PDF等公共文件，可按需创建
```

日常写作只修改 `content/`。页面布局、命令、输入、目录和字体等UI源码在 `site/`。`scripts/build-content.mjs` 解析内容与媒体；`scripts/build.mjs` 复制UI、生成内容、替换站点字段，成功后原子替换完整 `dist/`。`dist/` 已gitignore，不手改或作为内容源提交。

`content/site.yml` 顶层的 `name` 用于站点品牌，`greeting`、`role`、`interests` 和 `about.paragraphs` 用于首页问候与个人资料；顶层 `description` 已删除，不再填写，也不再生成对应的description meta标签。栏目名称与说明放在 `paths`，只维护 `description`，原 `introduction` 已合并删除。栏目固定使用 `life`（生活）、`resume`（经历）、`project`（项目），排列顺序由 `paths` 决定；文章归属由文章自己的 `sections` 决定，不必再维护一份文章列表。

`role` 只填写值，例如 `role: 学生`；界面自动添加“职业：”标签，以与关注行一致的普通次要文字色显示“职业：学生”，不要把标签或重复英文写进配置。“关注”行来自 `interests`，使用主区实际剩余宽度，空间不足时自然换行；`about.paragraphs` 仍保持可读限宽，窄屏不溢出。

个人介绍统一修改 `about.paragraphs`，只在首页显示；具体教育经历、技能或实践条目修改 `resume.sections`，在经历的展开全文中显示。经历概览始终保留“简历”一行：有PDF时显示可点击入口，没有时显示“PDF待添加”；展开全文不再重复PDF入口或首页资料。

进入生活、经历或项目，默认显示栏目标题、常驻 `description` 和最多10条最近内容，仅列日期与标题；不足10条按实际数量显示，不显示媒体数量。`open` 展开该栏目全部内容，`close` 返回概览；标题、说明及经历的简历行始终保留，展开时只切换最近列表与全文。左侧目录仍列出该分区全部内容，右侧本页目录只列文章内部章节，不把最近10篇标题再列一遍。

## 新增一篇内容

1. 在 `content/entries/` 下新建文件夹，例如 `my-note`。建议使用小写英文字母、数字和短横线。
2. 在文件夹中创建 `index.md`，填写顶部元信息和正文。
3. 将图片、视频等素材放在同一文件夹，在正文需要出现的位置写引用。
4. 使用下面的本地预览和检查流程核对结果。

```markdown
---
title: "文章标题"
sections: [project]
publishedAt: "2026-11-07"
---

这里写正文。

## 第一个小节

这里写这个小节的内容。

### 更具体的说明

需要时再增加下一层标题。
```

上面的日期仅示范格式。真实内容应填写真实日期，也可以删去日期字段。

| 元信息 | 如何填写 |
| --- | --- |
| `title` | 页面和左侧目录显示的标题；修改标题不改变链接。 |
| `sections` | 所属栏目。写 `[resume, project]` 可让同一篇内容出现在两个栏目，不需要复制文章或媒体。 |
| `publishedAt` | 可选创建/首次发布日期，格式为带引号的 `YYYY-MM-DD`；没有更新日期时用于列表排序。 |
| `updatedAt` | 可选的真实更新日期，格式相同，优先用于列表排序；未提供有效值时正文“更新于”回退显示创建日期，新建文章不必重复填写相同日期。 |

最近列表与左侧全量目录采用同一规则：优先有效 `updatedAt`，没有时采用 `publishedAt`，从新到旧排列；两者都没有时正常排在最后。正文标题下始终同时显示“创建于 … · 更新于 …”：创建日期读取有效 `publishedAt`，更新日期优先读取有效 `updatedAt`，没有时回退显示创建日期。沿用 `publishedAt` 表示创建/首次发布日期，不新增 `createdAt`。例如上面的文章只填创建日期，会显示“创建于 2026.11.07 · 更新于 2026.11.07”，无需手动填写相同的两份日期；只有更新日期时显示“创建于 — · 更新于 实际日期”，两者都没有时显示“创建于 — · 更新于 —”。回退只影响显示，不会自动改写Markdown或补保存 `updatedAt`，也不使用文件系统修改时间。旧文实际更新并填写真实 `updatedAt` 后可在列表前移。不设置独立的示例或示例日期元字段；内容性质通过正文自然说明。迁移的六篇排版示例保留了演示日期，每篇正文第一段明确说明日期和内容的用途。替换成真实内容时，也应一并核对日期和正文说明。

文件夹名是内容编号，例如 `geometry` 对应 `#project/geometry`。**改文件夹名会改变URL**，已有分享链接也需要同步更新；只改标题、正文或日期无需改文件夹名。

## 修改正文与本页目录

直接编辑对应的 `index.md`。文件顶部两行 `---` 之间是元信息，后面是 Markdown 正文。

文章标题来自 `title`，正文不必再重复写一次大标题。使用 `##` 写小节、`###` 写子节，程序根据这些真实标题自动生成本页目录；至少两个有效标题才显示。未手动选择时，主区可用宽度达到1000px则目录位于右侧180px列，其他宽度位于正文顶部、默认收起。点击章节只滚动终端正文并聚焦标题，不改变当前文章URL，也不需要另外编写目录数据。

可用 `Ctrl+Alt+A` 切换左侧内容目录，`Ctrl+Alt+B` 切换当前本页目录；工具栏也提供本页目录按钮与按键提示，手机仅显示图标。没有有效本页目录时隐藏该按钮，B组合键不处理。宽屏隐藏目录后释放右列；窄屏切换只展开/收起内容，顶部“本页目录”入口仍保留。手动选择会在本次会话跨文章与宽窄切换保留，刷新恢复默认。

命令输入中也能使用这两个组合键并保留草稿；IME组合输入、AltGr或其他编辑区不会触发。帮助正文在“操作”后提供“侧栏快捷键”组，A/B分别写作“显示/隐藏左侧目录”“显示/隐藏右侧目录”；底部紧凑区仍保留原有六条编辑快捷键。正文和工具栏继续使用“本页目录”。

原始HTML会显示为文本。图片与视频使用下述 Markdown 写法，不通过粘贴 `<video>`、`<iframe>` 等标签插入。

## 插入图片

将图片放在文章文件夹中，在希望显示的位置写：

```markdown
![图片内容的简要说明](./figure.png)
```

`./` 表示当前文章文件夹。说明应描述图中内容，便于图片无法显示时和使用屏幕阅读器的访客理解。需要补充来源、图注或解释时，可在图片后另写一段正文。

支持本地图片引用；图片按原始比例显示，较小的图片不会被强行放大填满阅读区。普通点击图片会在同页暗背景中居中预览；按 `Esc`、右上角的关闭按钮或图片外空白关闭，返回原图与原滚动位置。按住 `Ctrl`、`Meta` 或 `Shift` 点击仍沿用原图外链行为；无法使用同页预览时保留原图链接。原有Markdown写法无需修改，不增加轮播或缩放。一个条目可以引用多张图片或多个视频；分区概览不显示媒体数量。

## 插入MP4、封面与字幕

把MP4放在文章文件夹，在正文相应位置引用：

```markdown
![演示视频的简要说明](./demo.mp4)
```

程序按 `.mp4` 扩展名生成带原生播放控件的视频，不会把它当成图片，也不进入图片预览。只复制文件不会决定插入位置，**未在正文引用的素材不展示**。

封面和字幕放在同一文件夹，使用相同的视频文件名主体：

```text
demo.mp4
demo.poster.svg  # 可选封面；也可使用构建支持的其他图片格式
demo.zh.vtt      # 可选中文字幕
```

例如现有动画使用 `demo-orbit.mp4`、`demo-orbit.poster.svg`、`demo-orbit.zh.vtt`。只需在正文引用MP4，程序按同名约定查找封面与字幕；无需另外把封面作为图片插入。没有封面或字幕时，可以省略对应文件。

更换视频时，请同步核对封面、字幕和正文说明。当前迁移的几何动画是无声演示，原有说明继续保留。

## 添加或替换PDF简历

将文件放到 `content/files/resume.pdf`，然后在 `content/site.yml` 的 `resume` 下填写：

```yaml
resume:
  sections: []
  pdfUrl: "./files/resume.pdf"
```

构建会将公共文件复制到 `dist/files/`。不提供PDF时保留 `pdfUrl: ""`。替换同名PDF无需改链接；更换文件名时同步修改 `pdfUrl`。

## 本地预览与检查

以下命令在项目根目录运行。首次使用先安装依赖：

```powershell
npm ci
```

启动本地预览：

```powershell
npm run dev
```

保持预览终端开启，默认访问 [http://127.0.0.1:4182/](http://127.0.0.1:4182/)。开发服务监听 `content/` 与 `site/`，修改保存并成功重建后自动刷新浏览器；失败时查看终端说明并修正内容。结束预览时在该终端按 `Ctrl+C`。

完成编辑后运行检查与构建：

```powershell
npm test
npm run build
```

`npm test` 先构建站点，再运行全部 `tests/`；`npm run build` 也可单独将 `content/` 和 `site/` 生成完整发布目录。核对标题、所属栏目、日期、图片、视频、目录跳转和手机阅读效果后，再按项目分支流程提交。

推送 `main` 后会自动触发发布流程：先执行 `npm ci`，再执行包含构建的 `npm test`，通过后部署 `dist/`；最终状态以对应 GitHub Actions 任务结果为准。功能分支的提交或推送不自动更新线上网站。

发布自动按文件内容生成资源版本，替换同名图片、视频或PDF无需手改链接；发布后仍见旧页面时，可按 `Ctrl+F5` 强刷一次。
