# 中英文与自动翻译

网站共用一套页面、素材和文章标识。中文是内容源，英文在发布前生成。右上角的 `EN` / `中文` 按钮切换当前页面，不会回到首页；链接中的 `lang` 参数、个人语言选择和浏览器语言依次决定首次显示的语言，最后回退到中文。

## 首次配置

1. 在 DeepSeek 平台创建 API Key。
2. 打开 GitHub 网站仓库，进入 **Settings → Secrets and variables → Actions → New repository secret**。
3. 名称填 `DEEPSEEK_API_KEY`，值填你的 Key。
4. 推送到 `main`，或在 Actions 的 **Deploy website** 中选择 **Run workflow**。

密钥只用于 GitHub 的构建环境。不要写入文章、前端 JavaScript、配置文件或提交记录。示例环境文件是 `.env.example`；可以复制为被 Git 忽略的 `.env.local` 用于本地翻译。

当前仓库配置使用 `https://api.deepseek.com/chat/completions`、`deepseek-flash`、`high` 思考程度和 JSON 输出。模型与思考程度通过下文的集中配置调整；翻译提示词、术语表和批次限制位于 `scripts/translations.mjs`。

## 配置模型与思考程度

仓库根目录的 `translation.config.json` 是默认配置入口，不含 API Key：

```json
{
  "baseURL": "https://api.deepseek.com",
  "model": "deepseek-flash",
  "reasoningEffort": "high"
}
```

`model` 指定调用的模型，例如 `deepseek-flash` 或 `deepseek-v4-pro`。`reasoningEffort` 支持：

| 值 | 行为 |
| --- | --- |
| `none` | 关闭思考模式。 |
| `low` | 开启思考，使用低思考程度。 |
| `high` | 开启思考，使用高思考程度。 |
| `max` | 开启思考，使用最高思考程度。 |

例如，要改为 Pro 模型和高思考程度，把 `model` 改为 `deepseek-v4-pro`，把 `reasoningEffort` 改为 `high`。程序会自动设置 API 的 `thinking` 和 `reasoning_effort`，无需改请求代码。开启思考后不会发送不起作用的 `temperature`，也不会保存或发布模型返回的 `reasoning_content`。

也可以在 **GitHub 仓库 → Settings → Secrets and variables → Actions → Variables → New repository variable** 添加覆盖值，无需修改工作流：

| GitHub Variable / 本地环境变量 | 对应配置 | 文件和环境均未配置时的内置回退值 |
| --- | --- | --- |
| `DEEPSEEK_MODEL` | `model` | `deepseek-flash` |
| `DEEPSEEK_REASONING_EFFORT` | `reasoningEffort` | `none` |
| `DEEPSEEK_BASE_URL` | `baseURL` | `https://api.deepseek.com` |
| `DEEPSEEK_MAX_TOKENS` | `maxTokens` | 非思考 16384；开启思考 65536。 |
| `DEEPSEEK_TIMEOUT_MS` | `timeoutMs` | 非思考 60000；开启思考 180000。 |
| `DEEPSEEK_TEMPERATURE` | `temperature` | 0.2，仅非思考模式使用。 |

数值选项也可以直接添加到 JSON 配置中。优先级为：程序显式覆盖（供测试等使用）→ 非空环境变量 / GitHub Variables → `translation.config.json` → 内置默认值。GitHub Variables 没有填写时会使用配置文件。API Key 始终使用 Secret `DEEPSEEK_API_KEY`，不放进 JSON 或 Variables。

思考模式可能增加时间和 token 用量。更换模型或思考程度只影响下一次新增、改动的待翻译文字，已有缓存和人工修订继续保留，不会因此自动重译全部历史内容。自动生成的译文条目会记录使用的模型和思考程度。

参数依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 日常更新

仍然只需要编辑 `content/site.yml` 和 `content/entries/*/index.md`，然后预览、提交并推送。发布流程会：

1. 恢复已有英文译文。
2. 检测新增或变化的文字，只翻译这些段落。
3. 检查英文完整性、格式和网站功能。
4. 保存译文，再一起发布中英文。

如果 API 失败、额度不足、返回内容不完整或仍有缺失译文，本次发布会停止，线上继续保留上一次成功发布的完整网站。构建失败的信息可以在 Actions 中查看。

代码、公式、章节 ID、日期、链接、素材地址和命令名称保留原样。译文通过纯文本节点和限定的文字属性放回页面，模型返回的内容不能变成可执行 HTML。图片里已经写进去的中文、PDF 文件内容和视频字幕文件仍需单独制作英文版本。

## 译文存在哪里

- `content/translations/en.json`：源码随附的首版英文和你主动维护的英文修订。
- GitHub 的 `i18n-cache` 分支：每次自动翻译后保存的当前译文，只更新该分支的同名 JSON 文件，不回写 `main`，也不会循环触发部署。
- `dist/`：构建后的中英文内容与界面，不手工修改。

译文按“原文 + 术语表版本 + 翻译规则版本”的指纹复用。改动中文会产生新指纹，删除的段落会在下次翻译时清理。同一段原文共用译文；恢复缓存时，当前源码中的译文优先，因此你提交的人工修订不会被旧缓存覆盖。

工作流需要 `contents: write` 权限保存缓存分支，权限已在工作流中声明；`GITHUB_TOKEN` 由 GitHub 自动提供，不需要另配 Secret。缓存分支恢复和保存失败也会停止发布，以避免默默丢失译文。若给分支加保护规则，应允许此工作流更新 `i18n-cache`。

## 本地预览与翻译

已附带现有内容的首版英文，可以直接运行：

```powershell
npm run dev
```

普通预览允许尚未翻译的新段落暂时显示中文。发布构建则必须保证英文完整：

```powershell
npm run translate:check
npm run build:release
```

本地需要更新英文时，编辑 `.env.local`，填入 `DEEPSEEK_API_KEY`，然后运行：

```powershell
node --env-file=.env.local scripts/translate.mjs
```

也可以先在终端设置环境变量，再运行 `npm run translate`。翻译结果保存成功后，可以把希望保留在源码中的英文修订提交到 Git。翻译脚本不会自行提交或推送。

## 界面文字与语言链接

界面文字词典在 `site/assets/js/i18n.js`。组件通过 `t("中文文案")` 获取文字；构建还会收集 JavaScript 中这种双引号常量调用，把新增中文文案加入自动翻译。包含变量的文案应使用 `{name}` 等占位符，不能把姓名或数字先拼接进源文案。

中文文章链接示例为 `/?lang=zh#project/文章标识`，英文为 `/?lang=en#project/文章标识`。语言切换会保留主题参数和当前文章，并尽量按共享章节 ID 保留阅读位置。本方案沿用现有 hash 路由，尚未将每篇文章改为独立静态 HTML 地址。

左右目录的标题整行可点击收起；桌面收起后保留边缘展开按钮并释放正文宽度。手机保留左侧抽屉入口，文章目录在正文上方折叠；`Ctrl+Alt+A` / `Ctrl+Alt+B` 继续可用。
